# Методичка: как устроен `train.py` (обучение CRNN)

Цель: понимать каждую часть кода, уметь объяснить её на защите и переписать в свою структуру.

> Происхождение кода: скрипт создан с помощью ИИ-ассистента (Claude), запущен и проверен
> автором проекта на Cyrillic Handwriting Dataset (10 эпох на всём датасете:
> 84,32 % точность по символам, 40,89 % по словам).

---

## 1. Что делает программа в целом

Берёт картинки с рукописными словами и их правильные подписи, учит нейросеть
CNN + BiLSTM + CTC сопоставлять одно с другим, сохраняет лучшую версию модели
и записывает точность в `results.csv`.

```
data/train.tsv + data/train/*.png
      │  read_tsv
      ▼
список (путь, текст) → алфавит char2idx → HandwritingDataset → DataLoader (+ collate)
                                                                   │ пачки по 64 картинки
                                                                   ▼
                        CRNN → logits → log_softmax → CTCLoss → backward → шаг оптимизатора
                                         (повтор по всем пачкам = одна эпоха)
                                                                   ▼
        evaluate (greedy_decode + edit_distance) → сохранить лучшую → тест → results.csv
```

## 2. «Расписание»: что за чем идёт и что от чего зависит

### 2.1. Порядок этапов в `main()`

| № | Этап | Строки | Что нужно иметь ДО него | Что даёт дальше |
|---|------|--------|--------------------------|-----------------|
| 1 | Разбор аргументов (`argparse`) | 156–164 | ничего | `args.epochs`, `args.fraction` и др. |
| 2 | Семена и выбор устройства | 166–170 | – | `device` (cuda/cpu), `use_amp` |
| 3 | Чтение файлов с подписями (`read_tsv`) | 172–175 | `args.data` | `all_train`, `test_items` |
| 4 | Алфавит | 177–181 | `all_train` | `chars`, `char2idx`, `idx2char` |
| 5 | Разделение train / val, доля `fraction` | 183–189 | `all_train` | `train_items`, `val_items` |
| 6 | Три `DataLoader` | 191–199 | списки из шагов 3–5, `char2idx` | `train_loader`, `val_loader`, `test_loader` |
| 7 | Модель, функция потерь, оптимизатор, планировщик, scaler | 201–206 | `chars` (размер выхода), `train_loader` (число шагов) | `model`, `ctc`, `opt`, `sched`, `scaler` |
| 8 | Цикл по эпохам | 213–240 | всё выше | обученная модель, файл `models/*.pt` |
| 9 | Итоговая проверка на тесте | 242–247 | сохранённый файл из шага 8 | числа точности |

Главные зависимости:

- алфавит (4) нужен до `Dataset` (6), потому что `Dataset` переводит буквы в номера;
- размер выхода модели (7) = число букв + 1, поэтому модель создаётся после алфавита;
- `OneCycleLR` (7) требует знать `len(train_loader)`, поэтому создаётся после `DataLoader`;
- тест (9) запускается один раз, в самом конце, чтобы им не подгонять модель.

### 2.2. Порядок внутри одного шага обучения (строки 216–231)

Менять местами нельзя, каждая строка опирается на предыдущую.

| № | Строка | Зачем | Что будет, если нарушить порядок |
|---|--------|-------|-----------------------------------|
| 1 | `imgs.to(device)` | отправить пачку на видеокарту | ошибка: модель на GPU, данные на CPU |
| 2 | `logits = model(imgs)` внутри `autocast` | прямой проход, ответ модели | – |
| 3 | `logits.float().log_softmax(2)` | перевести ответ в логарифмы вероятностей | `CTCLoss` ждёт именно log-вероятности |
| 4 | `loss = ctc(...)` | посчитать, насколько модель ошиблась | – |
| 5 | `opt.zero_grad()` | обнулить старые градиенты | градиенты с прошлого шага сложатся с новыми |
| 6 | `scaler.scale(loss).backward()` | обратный проход: как менять веса | – |
| 7 | `scaler.unscale_(opt)` | вернуть градиентам настоящий масштаб | обрезка в шаге 8 сработает неверно |
| 8 | `clip_grad_norm_(..., 5.0)` | обрезать слишком большие градиенты | возможны скачки и `nan` |
| 9 | `scaler.step(opt)` | изменить веса | – |
| 10 | `scaler.update()` | подстроить масштаб для следующего шага | – |
| 11 | `sched.step()` | изменить скорость обучения (после шага оптимизатора, каждый батч) | – |

Режимы модели: `model.train()` ставится в начале каждой эпохи (до цикла по пачкам),
`model.eval()` ставится внутри `evaluate` (до проверки). В `train` работают dropout
и обновляется BatchNorm, в `eval` нет, поэтому проверять на режиме `train` нельзя.

## 3. Разбор по блокам

### 3.1. Константы

```python
IMG_H = 32      # высота, к которой приводятся все картинки
MIN_W = 32      # минимальная ширина
MAX_W = 400     # максимальная ширина (длинные подписи сжимаются)
```

- Нейросеть требует одинаковой высоты у всех картинок, а ширина может быть разной.
- Используются в `HandwritingDataset.__getitem__`, `collate` и сохраняются в чекпоинт,
  чтобы при распознавании приводить фото к тому же виду.

### 3.2. `read_tsv(tsv_path, img_dir)`

```python
def read_tsv(tsv_path, img_dir):
    items = []
    with open(tsv_path, encoding="utf-8") as f:
        for line in f:
            line = line.rstrip("\r\n")
            parts = line.split("\t", 1)
            if len(parts) < 2:
                parts = line.split(None, 1)
            if len(parts) < 2:
                continue
            name, text = parts[0], parts[1].strip()
            path = img_dir / name
            if text and path.exists():
                items.append((str(path), text))
    return items
```

- **Что делает:** читает файл построчно и возвращает список пар `(путь_к_картинке, текст)`.
- **Получает:** путь к `.tsv` и папку с картинками. **Возвращает:** список пар.
- **Кто вызывает:** `main()` дважды (для train и для test). **Что использует:** `open`, `Path`.
- **Когда:** в самом начале, до всего остального, потому что без списка нечего обучать.
- **Почему так:** `split("\t", 1)` режет только по первой табуляции, поэтому тексты
  с пробелами («продолжила борьбу») не разваливаются. Условие `path.exists()`
  пропускает записи, у которых нет картинки.

### 3.3. `HandwritingDataset`

```python
class HandwritingDataset(Dataset):
    def __init__(self, items, char2idx):
        self.items = items
        self.char2idx = char2idx

    def __len__(self):
        return len(self.items)

    def __getitem__(self, i):
        path, text = self.items[i]
        img = Image.open(path).convert("L")
        w, h = img.size
        new_w = min(max(round(w * IMG_H / h), MIN_W), MAX_W)
        img = img.resize((new_w, IMG_H), Image.BILINEAR)
        x = torch.from_numpy(np.asarray(img, dtype=np.float32) / 255.0)
        x = (x - 0.5) / 0.5            # белый фон -> 1.0
        target = [self.char2idx[c] for c in text if c in self.char2idx]
        return x.unsqueeze(0), torch.tensor(target, dtype=torch.long), text
```

- **Что делает:** по номеру `i` отдаёт один готовый пример: картинку-тензор и номера букв подписи.
- **Кто вызывает:** не вы, а `DataLoader` (он сам просит примеры и собирает из них пачки).
- **Что использует:** `Pillow` (открыть и изменить размер), `numpy` и `torch` (превратить в тензор), `char2idx`.
- **Когда:** каждый раз, когда `DataLoader` готовит новую пачку, то есть всё время обучения.
- **Три метода обязательны:** `__init__` (запомнить данные), `__len__` (сколько всего примеров),
  `__getitem__` (выдать пример).
- **Построчно в `__getitem__`:**
  1. `convert("L")` – чёрно-белая картинка (один канал вместо трёх);
  2. новая ширина = исходная ширина, пересчитанная под высоту 32, чтобы не искажать пропорции,
     и ограниченная между `MIN_W` и `MAX_W`;
  3. деление на 255 переводит значения пикселей в диапазон 0–1, затем `(x - 0.5) / 0.5` в диапазон −1…1;
  4. `unsqueeze(0)` добавляет ось «канал», форма становится `(1, 32, W)`;
  5. `target` – подпись, превращённая в номера букв.

### 3.4. `collate(batch)`

```python
def collate(batch):
    imgs, targets, texts = zip(*batch)
    max_w = max(im.shape[2] for im in imgs)
    out = torch.ones(len(imgs), 1, IMG_H, max_w)   # дополняем белым
    for k, im in enumerate(imgs):
        out[k, :, :, : im.shape[2]] = im
    in_lens = torch.tensor([max(im.shape[2] // 4, 1) for im in imgs], dtype=torch.long)
    t_lens = torch.tensor([len(t) for t in targets], dtype=torch.long)
    return out, torch.cat(targets), t_lens, in_lens, list(texts)
```

- **Зачем нужна:** картинки в пачке разной ширины, а тензор должен быть прямоугольным.
  Функция берёт самую широкую и дополняет остальные белым фоном справа.
- **Что возвращает (в таком порядке):** картинки, склеенные подписи, длины подписей,
  длины сигнала для CTC, исходные тексты.
- **Почему `// 4`:** два слоя `MaxPool(2,2)` уменьшают ширину в 4 раза, значит, модель выдаст
  `W // 4` шагов. CTC должен знать, сколько шагов настоящие, а не от белого дополнения.
- **Кто вызывает:** `DataLoader` (передаётся как `collate_fn=collate`).
- **Когда:** после `__getitem__`, перед тем как пачка попадёт в модель.

### 3.5. `CRNN`

```python
class CRNN(nn.Module):
    def __init__(self, n_classes):
        super().__init__()

        def block(i, o):
            return [nn.Conv2d(i, o, 3, padding=1, bias=False),
                    nn.BatchNorm2d(o), nn.ReLU(inplace=True)]

        self.cnn = nn.Sequential(
            *block(1, 64), nn.MaxPool2d(2, 2),                        # H 16, W/2
            *block(64, 128), nn.MaxPool2d(2, 2),                      # H 8,  W/4
            *block(128, 256), *block(256, 256), nn.MaxPool2d((2, 1), (2, 1)),  # H 4
            *block(256, 512), nn.MaxPool2d((2, 1), (2, 1)),           # H 2
        )
        self.rnn = nn.LSTM(512, 256, num_layers=2, bidirectional=True, dropout=0.2)
        self.fc = nn.Linear(512, n_classes)

    def forward(self, x):
        f = self.cnn(x)            # B, 512, 2, W/4
        f = f.mean(2)              # B, 512, T
        f = f.permute(2, 0, 1)     # T, B, 512
        f, _ = self.rnn(f)
        return self.fc(f)          # T, B, классы
```

Расшифровка букв: `B` – размер пачки, `T` – число шагов по ширине, `W` – ширина картинки.

| Часть | Что делает | Форма данных после |
|-------|------------|--------------------|
| вход | пачка картинок | `(B, 1, 32, W)` |
| `Conv2d + BatchNorm + ReLU` (блок) | находит штрихи и формы; BatchNorm стабилизирует обучение; ReLU добавляет нелинейность | число каналов растёт: 64 → 128 → 256 → 512 |
| `MaxPool2d(2, 2)` | уменьшает высоту и ширину вдвое | `H 16, W/2`, затем `H 8, W/4` |
| `MaxPool2d((2, 1), (2, 1))` | уменьшает только высоту, ширину не трогает (нужны шаги по горизонтали) | высота падает до 4, затем до 2 |
| `.mean(2)` | усредняет по высоте, остаётся одна «колонка» признаков на каждую позицию по ширине | `(B, 512, T)`, где `T = W/4` |
| `.permute(2, 0, 1)` | переставляет оси под формат LSTM «время, пачка, признаки» | `(T, B, 512)` |
| `LSTM` (двунаправленная, 2 слоя) | читает слева направо и справа налево, учитывает соседние буквы | `(T, B, 512)` (256 × 2 направления) |
| `Linear` | для каждого шага выдаёт оценки по всем буквам + «пусто» | `(T, B, n_classes)` |

- **Что использует:** `torch.nn`. **Кто вызывает:** `main()` создаёт модель, цикл обучения и `evaluate` вызывают `model(imgs)`.
- **Когда:** создаётся один раз после алфавита; `forward` вызывается на каждой пачке.
- **Почему `n_classes = число букв + 1`:** лишний класс это «пусто» (blank) для CTC.

### 3.6. `greedy_decode(logits, idx2char)`

```python
def greedy_decode(logits, idx2char):
    best = logits.argmax(2).transpose(0, 1).cpu().tolist()
    result = []
    for seq in best:
        out, prev = [], 0
        for k in seq:
            if k != prev and k != 0:
                out.append(idx2char[k])
            prev = k
        result.append("".join(out))
    return result
```

- **Что делает:** превращает ответ модели в текст. Для каждого шага берёт самую вероятную букву,
  потом применяет два правила CTC: повторяющиеся подряд буквы схлопываются в одну,
  символ «пусто» (0) выбрасывается.
- **Пример:** `п п р р _ и в в е _ т` (где `_` пусто) → `привет`.
- **Кто вызывает:** `evaluate` (а позже `recognizer.py`). **Когда:** после `model(...)`, когда нужен текст.

### 3.7. `edit_distance(a, b)`

```python
def edit_distance(a, b):
    prev = list(range(len(b) + 1))
    for i, x in enumerate(a, 1):
        cur = [i]
        for j, y in enumerate(b, 1):
            cur.append(min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (x != y)))
        prev = cur
    return prev[-1]
```

- **Что делает:** считает расстояние Левенштейна, то есть минимальное число вставок,
  удалений и замен, чтобы из одной строки получить другую. `привет` и `приват` = 1.
- **Работает и для строк (буквы), и для списков слов**, поэтому одна функция даёт и ошибку по символам, и по словам.
- **Кто вызывает:** `evaluate`.

### 3.8. `evaluate(model, loader, idx2char, device)`

```python
@torch.no_grad()
def evaluate(model, loader, idx2char, device):
    model.eval()
    ce = cn = we = wn = 0
    for imgs, _, _, _, texts in loader:
        with torch.autocast(device.type, enabled=device.type == "cuda"):
            logits = model(imgs.to(device))
        for pred, ref in zip(greedy_decode(logits.float(), idx2char), texts):
            ce += edit_distance(pred, ref)
            cn += len(ref)
            pw, rw = pred.split(), ref.split()
            we += edit_distance(pw, rw)
            wn += len(rw)
    char_acc = max(0.0, 1 - ce / max(cn, 1)) * 100
    word_acc = max(0.0, 1 - we / max(wn, 1)) * 100
    return char_acc, word_acc
```

- **Что делает:** прогоняет модель по проверочному набору и считает два числа.
  Точность по символам = 100 % − (ошибки / все буквы) = 100 % − CER.
  Точность по словам = 100 % − (ошибки в словах / все слова) = 100 % − WER.
- **`@torch.no_grad()`:** не считать градиенты (экономит память и время, учиться тут не нужно).
- **Когда вызывается:** в конце каждой эпохи (на `val_loader`) и один раз в конце (на `test_loader`).
- **Что использует:** модель, `greedy_decode`, `edit_distance`.

### 3.9. `main()` по этапам

**Аргументы и устройство (156–170).**

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
use_amp = device.type == "cuda"
```

`use_amp` включает смешанную точность (часть расчётов в 16 битах: быстрее и вдвое меньше памяти).

**Алфавит (177–181).**

```python
chars = sorted({c for _, t in all_train for c in t})
char2idx = {c: i + 1 for i, c in enumerate(chars)}
idx2char = {i + 1: c for i, c in enumerate(chars)}
```

Собираются все разные буквы из подписей и каждой даётся номер, начиная с 1. Номер 0 зарезервирован
под «пусто» (blank) для CTC. Алфавит строится по обучающим подписям, а не по тесту.

**Проверочная выборка и `fraction` (183–189).**

```python
random.shuffle(all_train)
n_val = max(200, int(0.02 * len(all_train)))
val_items = all_train[:n_val]
train_items = all_train[n_val:]
train_items = train_items[: max(1, int(len(train_items) * args.fraction))]
```

Сначала список перемешивается, из него отделяется 2 % на проверку (по ней выбирается лучшая эпоха),
потом из остатка берётся доля `fraction`. Благодаря `random.seed(0)` проверочная часть
одинакова во всех запусках, а меньшие выборки входят в большие.

**Модель, потери, оптимизатор (201–206).**

```python
model = CRNN(len(chars) + 1).to(device)
ctc = nn.CTCLoss(blank=0, zero_infinity=True)
opt = torch.optim.AdamW(model.parameters(), lr=args.lr)
sched = torch.optim.lr_scheduler.OneCycleLR(opt, max_lr=args.lr, steps_per_epoch=len(train_loader), epochs=args.epochs)
scaler = torch.amp.GradScaler("cuda", enabled=use_amp)
```

| Объект | Роль |
|--------|------|
| `CTCLoss` | считает ошибку между ответом модели и правильной подписью, не требуя знать, где какая буква. `zero_infinity` не даёт обучению сломаться, если картинка слишком короткая для подписи |
| `AdamW` | оптимизатор: меняет веса модели по градиентам |
| `OneCycleLR` | скорость обучения сначала растёт, потом плавно падает; вызывается после каждой пачки |
| `GradScaler` | защищает мелкие градиенты от обнуления при 16-битных расчётах |

**Цикл эпох (213–240).** Порядок внутри шага описан в таблице 2.2. После прохода по всем пачкам
вызывается `evaluate` на проверочной выборке, и если точность лучше прежней, модель сохраняется:

```python
torch.save({"model": model.state_dict(), "chars": chars,
            "img_h": IMG_H, "max_w": MAX_W}, out_path)
```

В файл попадают не только веса, но и алфавит и размеры картинки: без них готовую модель нельзя будет правильно использовать.

**Тест и запись результата (242–258).** После обучения загружается лучшая сохранённая версия,
один раз проверяется на `test` и результат дописывается строкой в `results.csv`.

## 4. Рекомендуемая структура для переписывания

```
src/
  data.py       константы, read_tsv, HandwritingDataset, collate
  model.py      CRNN
  metrics.py    greedy_decode, edit_distance, evaluate
  train.py      main(): аргументы, цикл обучения
  recognizer.py (позже) загрузка модели и функция recognize()
```

Кто откуда импортирует:

```python
# train.py
from data import read_tsv, HandwritingDataset, collate
from model import CRNN
from metrics import evaluate
```

Запускать нужно из корня проекта командой `python src/train.py`: тогда Python видит папку `src`
и импорты вида `from data import ...` работают. Циклических импортов нет: `metrics.evaluate` получает
модель как аргумент и сам её не импортирует.

## 5. Как это связано с сайтом (`recognizer.py`)

Сейчас `recognizer.py` возвращает тестовый текст. Позже в нём нужно:

1. Загрузить файл `models/...pt`: из него берутся `model` (веса), `chars` (алфавит), `img_h`, `max_w`.
2. Создать `CRNN(len(chars) + 1)` и загрузить веса; поставить `model.eval()`.
3. Привести фото к тому же виду, что при обучении (серое, высота 32, значения от −1 до 1).
4. Прогнать через модель и превратить ответ в текст через `greedy_decode`.

### 5.1. `preprocessing.py`: подготовка фото перед моделью

```python
import cv2
import numpy as np

from PIL import Image, ImageOps


def prepare_image(image: Image.Image) -> Image.Image:
    image = ImageOps.exif_transpose(image)
    image = image.convert("L")

    return image


def remove_noise(image: Image.Image) -> Image.Image:
    image_array = np.array(image.convert("L"))

    denoised_array = cv2.fastNlMeansDenoising(
        image_array,
        None,
        h=5,
        templateWindowSize=7,
        searchWindowSize=21
    )

    return Image.fromarray(denoised_array)
```

| Функция | Что делает | Зачем |
|---------|------------|-------|
| `prepare_image` | `exif_transpose` поворачивает фото так, как оно было снято; `convert("L")` делает его чёрно-белым (один канал) | Телефон хранит поворот в служебных данных, и без этого фото может оказаться «на боку»; чёрно-белое нужно, потому что модель принимает один канал |
| `remove_noise` | убирает шум методом Non-Local Means из OpenCV | выравнивает зернистость на фото при плохом освещении |

Параметры `cv2.fastNlMeansDenoising`:

| Параметр | Значение | Смысл |
|----------|----------|-------|
| `h` | 5 | сила очистки: больше убирает больше шума, но размывает тонкие штрихи букв |
| `templateWindowSize` | 7 | размер «кусочка», который сравнивается с другими (нечётное число) |
| `searchWindowSize` | 21 | в какой области ищутся похожие кусочки (нечётное число); чем больше, тем медленнее |

- **Кто вызывает:** пока только `test_preprocessing.py`. В `recognizer.py` и `app.py` эти функции не подключены.
- **Что использует:** `Pillow` (картинки), `numpy` (превращение в массив), `cv2` (сама очистка).
- **Порядок в будущем конвейере распознавания:**

| № | Шаг | Откуда |
|---|-----|--------|
| 1 | `prepare_image`: поворот по EXIF и перевод в серое | `preprocessing.py` |
| 2 | `remove_noise` (необязательно) | `preprocessing.py` |
| 3 | уменьшение до высоты 32 и нормализация | как в `HandwritingDataset.__getitem__` |
| 4 | модель → `greedy_decode` | `model.py`, `metrics.py` |

- **Почему шум убирают до уменьшения:** на фото с высоким разрешением шум хорошо виден, а после уменьшения до 32 пикселей по высоте штрихи уже слишком тонкие, и очистка только размоет буквы.
- **Что совпадает с обучением:** перевод в серое (`convert("L")`) делается и там, и там, поэтому шаг 1 безопасен.
- **Что НЕ совпадает с обучением:** в `train.py` очистки шума не было. Модель никогда не видела очищенных картинок, поэтому по умолчанию `remove_noise` лучше держать выключенной и включать, только проверив на реальных фото, что точность не падает.
- **Скорость:** Non-Local Means считается медленно, на фото в несколько мегапикселей это могут быть секунды. Это стоит учесть, потому что в требованиях заявлено время ответа 1–3 секунды. Проверить нужно на своём ноутбуке.
- **Чего эти функции не делают:** не вырезают слово или строку. Модель обучена на коротких вырезанных фрагментах, а в фото целой страницы одна строка займёт ничтожную долю картинки. Без поиска строк на странице распознавание будет плохим.

## 6. Типичные ошибки

| Сообщение / симптом | Причина | Что делать |
|---------------------|---------|------------|
| `CUDA out of memory` | пачка не помещается в видеопамять | `--batch 32` или `--batch 16` |
| `Устройство: cpu` | PyTorch без поддержки видеокарты | переустановить PyTorch с CUDA |
| точность 0 % после 1 эпохи на малой выборке | модель ещё ничему не научилась | это нормально, увеличить эпохи и данные |
| `loss` стал `nan` | слишком большая скорость обучения | уменьшить `--lr` |
| зависает на Windows с `workers` | особенность запуска процессов | `--workers 0` |
| `FileNotFoundError: data/train.tsv` | запуск не из корня проекта | `cd` в папку проекта |

## 7. Вопросы для самопроверки (с короткими ответами)

1. **Зачем картинкам одна высота?** Свёрточная часть и дальнейшие слои рассчитаны на фиксированную высоту; ширина может отличаться.
2. **Зачем `collate`?** Выровнять ширину картинок в пачке, дополнив белым фоном.
3. **Что такое эпоха?** Один проход по всем обучающим данным.
4. **Что такое batch?** Группа картинок, после которой обновляются веса (здесь 64).
5. **Зачем в CTC нужен «пустой» символ?** Чтобы отделять повторяющиеся буквы («лл») и пропускать участки без букв.
6. **Почему нельзя выбирать лучшую эпоху по тесту?** Тогда модель подгоняется под тест, и его результат перестаёт быть честным; поэтому есть отдельная проверочная часть.
7. **Чем точность по словам отличается от точности по символам?** Слово верно только без единой ошибки, поэтому точность по словам всегда ниже.
8. **Зачем `zero_grad` перед `backward`?** Иначе градиенты предыдущей пачки складываются с новыми.
9. **Что делает BiLSTM?** Читает признаки в обе стороны и учитывает соседние буквы.
10. **Почему на малом объёме данных точность ниже?** Модели не хватает примеров разных почерков; прирост от удвоения данных постепенно уменьшается (в измерениях: +6 п. п., затем +4 п. п.).

## 8. Ограничения текущей версии

- Читает короткие слова и строки (до 40 символов), а не целую страницу тетради.
- Школьные тетради (второй датасет) пока не используются: страницы нужно сначала нарезать на фрагменты.
- Нет аугментации (искажений картинок при обучении), поэтому на новом почерке точность может быть ниже.
- Декодирование «жадное» (берётся самая вероятная буква на каждом шаге); более точные методы (beam search) не применяются.
